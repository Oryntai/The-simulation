# Задание и доказательство замкнутого контура

`Task::load` читает TOML версии 1. `control` указывает документ управления относительно файла
задачи. Поле `profile` задаёт отдельный профиль эксплуатации для `sim-run --task`. Каждый `[[modes]]` имеет горизонт, требуемые окна до и после воздействия и максимальный
шаг записи. Все отметки времени — целые наносекунды от начала прогона. Начальные условия задаются
в `stimuli` с `at_ns = 0`. `excitation` указывает один из стимулов. Для него
`comparison_value` задаёт другое значение в парном опыте. Список `[[modes.faults]]` задаёт время
каждого отказа для отдельного прогона. `packet_delay` дополнительно требует `extra_delay_ns`.
Источники параметров имеют поля `kind` и `reference`. Допустимые виды — `datasheet`, `paper`,
`measured`, `derived`, `estimate`.

В полной матрице `[fault_sweep]` задаёт `at_ns`, источник и необязательное
`packet_delay_ns` для отказов без индивидуального расписания. При
`invariant_limits = true` пределы штатного опыта считаются обязательными и под
отказом. Для доказательства защиты нужен отдельный критерий реакции. Причины
нерассчитанных режимов из `[deferred_modes]` в профиле видны во всех их строках.

Каждая строка `[[criteria]]` указывает `case = { path, mode, fault? }`. `limits` — массив
ограничений `range` с `min` и/или `max` либо `forbidden` для двоичной истины. Сигнал задаётся
парой `{name, unit}`. `response` задаёт сигнал физического отклика, `min_change`, `within_ns` и
источник. Задержка реакции считается от фактического воздействия до первого измеренного изменения
не меньше порога относительно последнего значения до воздействия. Границы включительные.
Пример данных с матрицей записан в генераторе `tests/support/mod.rs`.

Сборщик передаёт `Topology` после разрешения проводки, модели и каналов. В ней профиль эксплуатации
задаёт обязательные режимы, пути привязаны к приводам мира, а обязательные инъекции выводятся из
типов узлов. Отсутствие режима, сценария отказа или критерия в файле оставляет строку матрицы
открытой. Для каждого пути указываются регулятор с отпечатком программы, наблюдение, семантическая
единица команды, опубликованное принятие, доступные ряды физического отклика и участки доставки с отдельными идентификаторами для каждого направления.
`limitation_paths` сужает известные ограничения к связанным путям. Неизвестная тема блокирует
доказательство по всем путям.

`Assessor::execute` передаёт установщику свежий рантайм, `RunPlan` и `EventSink`. Установщик
возвращает отпечатки **фактически установленных** входов. Для обоих опытов стимулы берутся через
`RunPlan::stimulus_value`. Контроллеру передаются только разрешённые сигналы, и он не получает
план или вид опыта. Изменение возбуждения проходит через модель. Для парного опыта до возбуждения
проверяется совпадение входного и выходного ряда. После него проверяется различие реально
доставленного измерения и живой команды в совпадающий момент.

Компоненты пишут в `EventSink` в ходе исполнения. При применении стимула и отказа фиксируются
запрошенный и фактический моменты. Для отказа узла нужен двоичный ряд фактического состояния из
модели, где 1 означает действующий отказ. Для связи нужны реальные `Transfer` с отметкой
отправки и исходом доставки. Законченный `Cycle` несёт один номер обмена от измерения до свежего
обратного измерения. Указываются исходный момент измерения или съёмки, доставка, чтение,
идентификатор живого издателя команды, команда и фактическое принятие исполнительной моделью.
Оценщик сверяет измерения, источник команды и значение принятия с журналом рантайма. Двоичные
состояния и физические ряды берутся из истины. Источниками этих событий служат модели и сборщик.

`execute_recorded` дополнительно отдаёт журналы обоих опытов архиватору. Отпечатки журналов есть
в `CaseReport`. `execute_observed` предоставляет тому же архиватору доступ к журналу
событий установленного контура через рантайм.
`Assessor::assess` объединяет строки по полной матрице и ожидаемой версии входов.
`Evidence` сериализуется для отчёта. Входа для загрузки доказательства из произвольного отчёта нет.
Нерассчитанное окно или ограничение модели оставляет `NotAnalyzed`. Измеренное нарушение имеет
приоритет над пробелом. Любой `Pass` относится к конкретным порогам, модели и покрытым воздействиям.


При наличии типизированного журнала `sim-runtime::control` оценщик принимает
события из живого экземпляра контура. Команда требует `ModelAcceptance` со
сквозным номером. Для внешнего процесса сверяется содержимое фактически
доставленного запроса. Отметка `ModelReport` по совпавшему числу служит
диагностике. Поле `diagnostic_comparison` позволяет получить парные измерения
и при ограничениях модели. Такая сверка не снимает ограничения.

## Кампания версии 1

В корне задаются `version = 1`, `seed`, пути `world` и `catalog`.
`include` подключает документы версии 1 с дополнительными `stations`. Пути в каждом
документе разрешаются относительно этого документа. Циклы, повтор постановки,
неизвестные поля и неконечные числа запрещены. Каталог может быть файлом или каталогом ресурсов.

```toml
version = 1
seed = 7
world = "world.toml"
catalog = "catalog"
include = ["series.toml"]

[stations.carriage]
experiment = { kind = "scenario" }

[stations.carriage.modes.motion]
horizon_ns = 4000000
source = { kind = "derived", reference = "программа синтетического стенда" }
steps = [
  { id = "push", target = { kind = "effort", name = "carriage/push" }, at_ns = 0, value = 2.0, unit = "N", source = { kind = "derived", reference = "сила стенда" } }
]
criteria = [
  { id = "travel", window = "whole", limit = { kind = "range", signal = { name = "qpos[0]", unit = "m" }, min = 0.0, max = 0.1, source = { kind = "derived", reference = "рабочий ход стенда" } } }
]

[stations.carriage.modes.motion.windows.whole]
start_ns = 0
end_ns = 4000000
max_gap_ns = 1000000
```

`experiment.kind` также принимает `control`, `process`, `interaction` со ссылкой `task`.
Постановка может ссылаться на `profile`. Кампания проверяет оболочку задания,
ссылку на проводку или профиль и конечность чисел. Каталоги, варианты чужих профилей,
ресурсы проводки и остальные зависимости проверяет адаптер их формата. Для **каждой**
ссылки из `Campaign::references` он передаёт в `ResolvedInputs.references` отпечатки файла
и полного проверенного графа. Состав, обязательные режимы, сетки и применимые отказы
поступают в `ResolvedInputs.paths` до применения фильтров. Для контура их можно вывести
через `RequiredPath::from_topology`. Синтаксис старых заданий сохраняется.

Действия `steps` упорядочены по `at_ns` и адресуют `effort`, `port` или `operation`.
`max_lag_ns` разрешает указанное опоздание фактического применения. Если поле
опущено, фактическое время должно совпасть с запланированным.
`poses` задаёт полную позу `placement`, `link` или `object`. `initial` задаёт
типизированные начальную координату, скорость, координату позы или среду. Два
наложения одного параметра, два действия на одном ресурсе в один момент и неверные
единицы дают ошибку. `criteria` читает истину из журнала, проверяет обе границы окна,
разрывы и включительные пределы `range` либо двоичный запрет `forbidden`.

`faults` задаёт `fault = { node, kind }`, `at_ns`, `max_lag_ns`, обязательное
`window`, `source` и `extra_delay_ns` для `packet_delay`. Окно начинается до
запланированной инъекции и заканчивается после её самого позднего момента.
`combinations` задаёт `path`, `faults` и `source`. Совместные отказы из профиля
и из задания объединяются. Конфликт на одном ресурсе, отсутствие механизма,
расписания или результата сохраняют открытую строку. Неприменимость требует
основания из разрешённого состава и надёжного источника. Объявленная
неприменимость без проверяемого основания оставляет обязательство открытым.

### Разброс и воспроизведение

Каждая `sampling.axes` задаёт `id, parameter, unit, nominal, source, scope` и
либо непрерывный интервал `min, max`, либо конечный список `values`. В конечном
списке номинал обязателен и значения уникальны.
`scope` принимает `batch`, `specimen` или `run`. Номинал сверяется с разрешённым миром.
Поддержаны координаты кадра размещения, звена или предмета в метрах, масса тела в
килограммах, трение явной пары, шум, смещение и задержка датчика, задержка канала,
начальная скалярная координата и обобщённая скорость, гравитация, ветер, плотность и вязкость.
Для массы при фиксированной геометрии тем же коэффициентом масштабируются инерция
и источники плотности или масс объёмов. Единица трения кручения и качения — метр,
касательного трения — `1`. Единицы шума и смещения сообщает разрешённая модель датчика.
Задержки задаются в секундах. Задержка проводки явно округляется вверх до наносекунды
в `SampledInputs.settings.channel_delay_ns`. Ненулевая начальная скорость требует
поддержки установщика до первого такта. Оценщик сверяет квитанцию с состоянием
MuJoCo, настройкой канала и временем живой доставки.

`sampling.boundaries` перечисляет пробы `{ id, values = { ось = значение }, source }`.
Оси вне перечисленной комбинации сохраняют номинал. Пропуск `sampling`, пустой
набор осей и единственное различимое состояние блокируют положительный
вердикт. При наличии вероятностного закона требуются хотя бы две различимые
случайные выборки. По конечным осям план добавляет все комбинации, которых
нет среди номинала и явных проб. Смешанная постановка также исполняет эти
комбинации на номиналах непрерывных осей. Непрерывный интервал остаётся открытым
даже после исполнения всех указанных границ. Необязательная запись
`sampling.discrete` связывает источник со списком ручных `boundary_ids`. Для вероятностной серии нужны
`sampling.probability` с `batches`, `specimens` на партию, `repeats` на образец,
`confidence`, `independence` и `source`. Закон `batch` имеет `source` и
`alternatives` с идентификаторами, положительными весами и картой совместных значений.
`specimen` задаёт закон для каждой альтернативы `batch`, а `run` — для каждой пары
альтернатив `batch` и `specimen`. Даже уровень без осей задаёт явную альтернативу
с пустой картой. Значение оси задаётся как `{ kind = "fixed", value }` или
`{ kind = "uniform", min, max, factor, from? }`. Одинаковое имя фактора на том же
уровне задаёт один квантиль. Разные имена задают независимые факторы по допущению
профиля. `from` берёт фактор определённого родительского уровня. Закон и область
источника проверяются для всех ветвей до запуска.

Ключ содержит постановку, режим, путь, набор отказов, вид выборки, номера партии,
образца и повтора от нуля и сетку. `CampaignPlan::materialize` возвращает копию
входов и вектор выборки с источниками и всеми зёрнами. Для одного опыта вложенные
сетки и парный опыт используют тот же вектор и зерно. `WorldInputs::compile`
применяет сетку и параметры мира. Установщик отдельно применяет настройки
проводки и начальные скорости и возвращает фактически установленные значения,
зерно, сетку и отпечаток входов в `Installation`.

В манифесте CLI опыт `kind = "task"` принимает свой раздел `sampling` либо
наследует `assemblies.<id>.sampling` и его корневое `seed`. На всех сетках
каждого опыта применяется тот же совместный вектор значений. Профиль по-прежнему
задаёт собственные обязательные режимы и отказы. Отчёт включает инвентаризацию
фактически разрешённой модели, выборку и считанные установки.

Для каждого режима процессов или взаимодействия `snapshot_ns` задаёт момент
сверки продолжения со снимка с непрерывным исполнением. `--checkpoint` в
кампании сохраняет завершённые строки с выявленным нарушением и привязывает
их к исполняемому файлу, MuJoCo и входам. При изменении входа строка исполняется
заново с исходным зерном. Сверка по журналу внешней программы оставляет
изоляцию и состояние процесса открытыми.

### Метрики и сводка

Массив `metrics` связывает `id, signal, series, reference, window, interpolation,
operation, worse, source` и необязательный `limit`. `series` принимает `truth`
или `observation`. Опора `constant`, `series` или `step` имеет единицу сигнала;
ступень ссылается на `stimulus` и задаёт `before` и `after`. Временные метрики
используют фактическое время подтверждённого действия, границы окна и явное
правило `linear` или `hold`. Доступны операции `absolute` с `at_ns`,
`tracking_rms`, `settling` с `band` и необязательным `deadline_ns`,
`overshoot` и `overshoot_fraction`. Время установления публикуется в наносекундах
с округлением входа в полосу вверх. Отсутствие подтверждённого установления до
конца полного окна отмечается правым цензурированием. Доля ступени при нулевой
амплитуде остаётся открытой.

`evaluate_scenario` сверяет общий критерий с журналом и подтверждёнными действиями.
`FaultObservation::from_state` проверяет двоичное состояние именованной модели
до и после инъекции. Каналы доставки и ссылочные задания предоставляют свои
живые наблюдения через адаптер. `summarize` проверяет принадлежность к полной
матрице, применённые входы и горизонт. Публикует долю среди классифицированных
и границы по всем применимым строкам. Отчёт содержит отдельные серии для
детерминированных проб и случайных выборок.

Интервал Клоппера–Пирсона требует полной серии и `independence = "batches"`
с одним образцом и одним повтором на партию или `"within_batch"` с одним
повтором на образец и отдельным интервалом для каждой партии. Вложенные
повторы и зависимые образцы оставляют общий интервал открытым. Медиана, P95
и худший ключ относятся к точным значениям и публикуются с числом точных и
цензурированных результатов. Повторяемость `среднее + 3σ` вычисляется по полной
серии независимых абсолютных ошибок при одинаковых установленных условиях.
Статистика описывает выполнение задания. Доказательства опасностей и
ступени пригодности рассчитываются отдельным оценщиком.

### Обязательства и вердикт кампании

Разрешитель собирает `ResolvedInventory` из мира, состава, каталога, топологии,
насадок и профиля эксплуатации. `derive_requirements(&inventory, &plan)`
выводит ключи из этого состава до фильтра исполнения. Для каждого домена
нужно основание полноты или причина пробела. Необходимо указать достижимость
участника и идентичность сборки. Неописанные опасности насадки следуют из её
`WorkSubject`. Неизвестные классы остаются в отчёте с исходным идентификатором.
Постановка может добавить обязательства в `modes.<mode>.hazards`. Запись
содержит `class`, `object`, имя `window` и `source`. Список дополняет состав.

Реестр экспортируют `REGISTRY` и `REGISTRY_VERSION`. Разрешённый профиль
привязывает `Check` к классу, объекту, режиму, окну и проверочному методу.
Для производных источников таблица `derivations` содержит непосредственные
входы по ссылкам. Каждый путь до исходных данных проверяется рекурсивно.
Для кампании с конечными выборками область вывода включает только проверенные
состояния. Выход на непрерывный допуск требует обоснованной огибающей.

`CampaignEvidence` создаётся для конкретного набора требований. `execute`
запускает на двух свежих экземплярах один материализованный ключ и сверяет
журналы. `execute_timed` дополнительно применяет расписание усилий и передаёт
операции установщику. Для профиля, добавляющего фрагменты, `execute_linked`
сверяет расширенный скомпилированный мир с отпечатком из инвентаря.
Для ссылочной постановки также требуется отпечаток критериев в `linked_profiles`.
Установщик подтверждает реально применённые настройки, сборку и параметры.
Отказ сверяется по живому сигналу состояния либо по подтверждённому контуру.
`record_unavailable` сохраняет причины фильтрации и ошибок сборки.

`record_control`, `record_process` и `record_interaction` привязывают
результат существующего оценщика по журналу, а `Check` сверяет профиль,
критерий, объект и окно. Для оценки процесса сверяются три вложенные сетки.
Для человека давление и силы конструкции и тканей проверяются отдельно.
Достижимые пути электрической, тепловой и механической энергии имеют
самостоятельные обязательства. `record_measurement` сверяет версию, ключ
опыта, канал и окно стендового ряда с требованием. Измерение принимает
доверенный адаптер формата с указанием установки и калибровки.

`assess_campaign` возвращает сериализуемый `VerdictReport` с находками,
открытыми обязательствами и основаниями неприменимости. В численном пределе
`lower` и `upper` задаются независимо, каждый как интервал неопределённости.
Наблюдавшееся нарушение сохраняется вместе с пробелами. Подтверждение класса
для отрицательного корпуса требует применимого свидетеля помимо нарушения
порога постановки. Статистика и JSON пригодны для отчёта. Положительный
вердикт строится из живых данных. Для полной аппаратной готовности нужны
применимые замеры, привязанные к версии сборки.
