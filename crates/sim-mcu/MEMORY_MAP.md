# VMCU-C3 — виртуальный микроконтроллер `sim-mcu`

Ядро — как у ESP32-C3: **RV32IMC + Zicsr, 160 МГц, только машинный режим**.
Периферия — **своя, простая** (регистры ESP32-C3 не эмулируются). Прошивки —
настоящие ELF, собранные `rustc` под `riscv32imc-unknown-none-elf` (`firmware/`).

## 1. Ядро

| Что | Как сделано |
|---|---|
| Команды | RV32I, M (mul/mulh/mulhsu/mulhu/div/divu/rem/remu, деление на 0 и INT_MIN/−1 — по табл. 7.1), C (все коды RV32C без F/D), Zicsr, `fence`/`fence.i` (nop), `ecall`, `ebreak`, `mret`, `wfi` |
| Источник | спецификация RISC-V (Volume I 20191213, Volume II 20211203); код других эмуляторов (QEMU и пр.) не использован |
| CSR | `mstatus` (MIE, MPIE; MPP читается как 11), `misa` = 0x4000_1104, `mie`, `mip` (только чтение), `mtvec` (прямой и векторный режим), `mscratch`, `mepc`, `mcause`, `mtval`, `mcycle[h]`, `minstret[h]` (запись допустима), `cycle/time/instret[h]` (только чтение), `mhartid`/`mvendorid`/`marchid`/`mimpid` = 0, `mstatush` = 0, `mcountinhibit` = 0. Иной CSR или запись в CSR только для чтения — недопустимая инструкция |
| Исключения | недопустимая инструкция (2, `mtval` = биты), невыровненные загрузка/запись (4/6, `mtval` = адрес; выравнивание **обязательно**, программная эмуляция невыровненного доступа не делается), ошибки доступа при выборке/загрузке/записи (1/5/7), `ecall` (11). Все доставляются прошивке через `mtvec` |
| `ebreak` | останов «в отладчик»: ядро и периферия замирают, хост видит `HaltReason::Breakpoint` |
| Прерывания | MEI (11, внешнее, от INTC) > MSI (3, CLINT.MSIP) > MTI (7, таймер). Берутся на границе инструкции при `mstatus.MIE = 1` |
| `wfi` | если нет ожидающего разрешённого (в `mie`) прерывания — ядро спит, время **проматывается** до ближайшего события (таймер, сторож, конец шага хоста). Просыпается и при `mstatus.MIE = 0` (продолжает без ловушки) |
| Сбой → хосту | (а) исключение-сбой внутри обработчика исключения (до `mret`) — «двойной сбой»; (б) одно и то же исключение по одному адресу 64 раза подряд; (в) прошивка записала SYSCTRL.FAULT_CAUSE (так делает обработчик по умолчанию `vmcu-hal`). Ядро останавливается, хост получает `Fault { kind, cause, pc, tval, source }`; хост никогда не паникует. Периферия держит последние значения, включённый сторож продолжает счёт и сбросит микросхему — как в железе |

**Модель времени (приближённая, «оценка»)**: 1 такт на инструкцию плюс:
загрузка +1; доступ к периферии/CLINT +4; выполненный условный переход +2;
`jal`/`jalr` +2; умножение +1; деление +32; CSR +1; вход в ловушку +4; `mret` +2.
Кэш флеша всегда попадает, конвейер не моделируется. Погрешность оценки загрузки
ЦП и задержек — порядка ±30 %.

## 3. Регистры

### CLINT (0x0200_0000)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x0000 | MSIP | RW | бит 0 — программное прерывание |
| 0x4000 / 0x4004 | MTIMECMP lo / hi | RW | после сброса 2⁶⁴−1 |
| 0xBFF8 / 0xBFFC | MTIME lo / hi | R | **16 МГц** (1 тик = 10 тактов); общее время модели, сбросом не обнуляется |

Прерывание таймера ожидает, пока `mtime ≥ mtimecmp`. Безопасная запись — как в
Privileged ISA 3.2.1: lo ← 0xFFFF_FFFF, hi, lo.

### SYSCTRL (0x6000_0000)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 | ID | R | 0x5643_3343 |
| 0x04 | RESET_REASON | R | 1 — питание, 2 — сторож, 3 — программный |
| 0x08 | WDT_RESETS | R | сбросов сторожем с включения питания |
| 0x0C / 0x10 | TIME_US lo / hi | R | время модели, мкс |
| 0x14 | CPU_HZ | R | 160 000 000 |
| 0x18 | HALT | W | останов, значение — код выхода (для тестов) |
| 0x1C | SW_RESET | W | ключ 0x5257_5354 — программный сброс |
| 0x20 | FAULT_PC | RW | адрес сбоя (пишет обработчик) |
| 0x24 | FAULT_TVAL | RW | `mtval` сбоя |
| 0x28 | FAULT_CAUSE | W | запись останавливает ядро как «сбой, сообщённый прошивкой» |
| 0x2C | BOOT_COUNT | R | сбросов любого рода с включения питания |

### GPIO (0x6000_1000), 32 вывода
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 | OUT | RW | выходные уровни |
| 0x04 / 0x08 / 0x0C | OUT_SET / OUT_CLR / OUT_TOGGLE | W | единицы ставят / сбрасывают / инвертируют биты OUT |
| 0x10 | DIR | RW | 1 = выход |
| 0x14 | IN | R | выход → OUT, вход → уровень от хоста |

После сброса все выводы — входы. Входы от хоста по умолчанию высокие (подтяжка).
`Mcu::gpio_output(pin)` = вывод настроен на выход **и** выдаёт 1.

### PWM (0x6000_2000), 4 канала, канал n по 0x10·n
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| +0x0 | DUTY | RW | 0..=65535 (65535 = 100 %), больше — насыщается |
| +0x4 | FREQ_HZ | RW | частота несущей, по умолчанию 20 000 |
| +0x8 | CTRL | RW | бит 0 — включён |

Усреднённая модель: хост видит `pwm_duty(ch) = DUTY/65535` (выключенный — 0).

### ADC (0x6000_3000), 8 каналов, 12 бит, Vref = 3.3 В
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 + 4·n | DATA[n] | R | чтение = мгновенное преобразование: `clamp(floor(V·4096/3.3), 0, 4095)` |
| 0x40 | VREF_MV | R | 3300 |
| 0x44 | BITS | R | 12 |

Идеальный АЦП (без шума, нелинейности, времени преобразования) — шум, если нужен, добавляет хост.

### UART0 (0x6000_4000)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 | TXDATA | W | младший байт → строковый буфер хоста (`uart_take`) |
| 0x04 | RXDATA | R | байт из FIFO приёма (256 байт); пусто → бит 31 |
| 0x08 | STATUS | R | бит 0 — есть байт, бит 1 — TX готов (всегда), биты 16.. — число байт |
| 0x0C | RX_DROPPED | R | потерянные при переполнении |

Скорость линии не моделируется. Прерывание INTC бит 0 — пока FIFO приёма не пуст.

### RADIO (0x6000_5000) — пакетное радио (BLE/Wi-Fi-подобное)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x000 | STATUS | R | бит 0 — есть пакет; бит 1 — очередь TX полна; биты 8–15 — пакетов RX; 16–23 — пакетов TX |
| 0x004 | TX_LEN | W | длина 1..=251 — отправить TX_BUF[0..len]; иное — в TX_DROPPED |
| 0x008 | RX_LEN | R | длина головного пакета (0 — нет) |
| 0x00C | RX_RSSI | R | RSSI головного пакета, дБм, знаковое |
| 0x010 | RX_POP | W | снять головной пакет |
| 0x014 | TX_DROPPED | R | |
| 0x018 | RX_DROPPED | R | |
| 0x100–0x1FB | TX_BUF | RW | |
| 0x200–0x2FB | RX_BUF | R | данные головного пакета |

Очереди — по 8 пакетов. Эфир (задержки, потери, RSSI) — забота хоста (`sim-radio`):
`radio_take_tx()` забирает отправленное, `radio_deliver(bytes, rssi)` кладёт принятое.
Прерывание INTC бит 1 — пока очередь приёма не пуста.

### WDT (0x6000_6000)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 | CTRL | RW | бит 0 — включён (запись запускает отсчёт заново) |
| 0x04 | TIMEOUT_US | RW | по умолчанию 1 000 000 |
| 0x08 | KICK | W | ключ **0x0D06_F00D** перезапускает отсчёт; иное игнорируется |
| 0x0C | REMAINING_US | R | |

Истечение → сброс микросхемы (ядро и периферия; ОЗУ и CONFIG сохраняются),
RESET_REASON = 2, WDT_RESETS + 1, сторож выключается.

### INTC (0x6000_7000)
| Смещение | Регистр | Доступ | Описание |
|---|---|---|---|
| 0x00 | PENDING | R | уровни: бит 0 UART RX, бит 1 RADIO RX |
| 0x04 | ENABLE | RW | маска |

`MEIP = (PENDING & ENABLE) ≠ 0`; источники уровневые.

### Сбросы
| | ядро | периферия | ОЗУ | CONFIG | счётчики сбросов |
|---|---|---|---|---|---|
| `Mcu::reset()` (питание) | да | да | обнуляется | сохраняется | обнуляются |
| сторож / программный | да | да | сохраняется | сохраняется | +1 |

Входы от хоста (АЦП, GPIO-входы), уже переданные пакеты и вывод UART сбросом не трогаются.

## 4. Интерфейс хоста (кратко)

```rust
let mut mcu = Mcu::from_elf(&bytes)?;            // PT_LOAD по физическим адресам (.data — во флеш)
mcu.write_config(&ExoConfig::default().to_bytes())?;  mcu.reset();
mcu.run_for(dt)?;                                // 160 МГц, с промоткой сна; Err — только неверный dt
mcu.time(); mcu.cycles(); mcu.instret(); mcu.cpu_load();
mcu.set_adc_volts(ch, v); mcu.set_gpio_input(pin, high); mcu.gpio_output(pin);
mcu.pwm_duty(ch); mcu.uart_take(); mcu.uart_send(&b);
mcu.radio_take_tx(); mcu.radio_deliver(&b, rssi_dbm);
mcu.fault(); mcu.halt_reason(); mcu.watchdog_resets(); mcu.pc(); mcu.reg(i); mcu.symbol("имя");
```

## 5. Прошивки (`firmware/`)

* Отдельный workspace, только `core`, без внешних зависимостей. Сборка:
  `firmware/build.sh` → `assets/firmware/{selftest,exo-ctrl}.elf` (их же встраивает
  `sim_mcu::firmware`). Профиль: `opt-level = "s"`, LTO, `panic = "abort"`.
* `vmcu-hal`: `link.x` (FLASH/RAM как выше, `.data` AT>FLASH), стартовый код
  (`_start`: стек, копия `.data`, обнуление `.bss`, `mtvec`), вход в ловушку
  (сохраняет 16 регистров), диспетчер (таймер / внешнее / программное /
  исключения), паника → текст в UART и SYSCTRL.HALT = 0xDEAD_0001, обёртки периферии.
* `selftest-core`: чистые функции; тот же исходник собирается нативно хостом.
* `selftest`: печатает `ST <ключ> <hex>`, `SYS <ключ> <hex>`, ждёт 16 байт по UART
  после `SYS rx.ready 1`, завершает `ST end N` и HALT = 0.

и держится там до команды режима 0, флаг `CONTACT` (бит 2 второго байта). Драйвер не выключается,
чтобы груз не упал. Если за 1 с рука не отошла больше чем на 2° от цели отвода — спад тока как при
заклинивании.

Поля 0x6C..0x80 появились в версии 2, 0x84..0x88 — в версии 3, 0x8C..0x90 — в версии 4 (дописываются в
конец, CRC всегда последний); блоки младших версий прошивка отвергает. Значения по умолчанию для них — maxon EC 90 flat
260 Вт (500267). Полный согласованный набор для привода maxon + Harmonic Drive
CSG-25-50 — `ExoConfig::maxon_ec90flat_hd50()`.

Блок не принят (магия, версия, размер, CRC или величины вне разумных пределов:
все физические величины > 0, `t_winding_max_c` > 25 °C) →
значения по умолчанию и бит `state.5`. Хост: `sim_mcu::exo::ExoConfig::to_bytes()`.
Параметры по умолчанию — «оценка» (мотор 0.05 Н·м/А, редуктор 100:1 с КПД 0.8,
батарея 6S, предплечье с кистью 1.65 кг по таблицам Winter, 2009).

### Радиопротокол
Команда телефон → экзоскелет (8 байт):

| Байт | Поле |
|---|---|
| 0 | 0xC1 |
| 1 | режим: 0 — выкл, 1 — гравитационная поддержка, 2 — слежение за положением |
| 2 | поддержка, % (0..100, больше — 100) |
| 3–4 | цель, °×10, u16 LE (ограничивается 0..150°) |
| 5–6 | груз в кисти, кг×10, u16 LE (до 20 кг) |
| 7 | seq |

Телеметрия экзоскелет → телефон каждые 20 мс (14 байт; к 13-байтному формату
версии 1 в конец дописан байт 13, прежние поля не менялись):

| Байт | Поле |
|---|---|
| 0 | 0x7E |
| 1 | state: биты 0–1 режим; 2 драйвер включён; 3 снижение тока по температуре; 4 запуск после сброса сторожем; 5 работают значения по умолчанию; 6 связь есть (команда не старше 500 мс) |
| 2–3 | угол, °×10, u16 LE (средний за 1 мс; ниже 0 — 0) |
| 4–5 | ток, А×100, i16 LE (средний за 1 мс) |
| 6–7 | температура корпуса (ADC2), °C×10, i16 LE |
| 8–9 | Vbat, В×100, u16 LE |
| 10 | fault_flags (ниже) — всё, что было с прошлого пакета |
| 11 | seq телеметрии |
| 12 | seq последней принятой команды |
| 13 | fault_flags2: бит 0 STALL, бит 1 WINDING_HOT — всё, что было с прошлого пакета |

Хост: `ExoCommand::encode/decode`, `ExoTelemetry::encode/decode` (ровно 14 байт),
`ExoTelemetry::all_faults() -> u16` (= fault_flags | fault_flags2 << 8),
`exo::fault::names(u16)`.

### Диагностический блок `EXO_DIAG` (ОЗУ, символ в `.symtab`, обновляется каждую 1 мс)
То, что инженер читает отладчиком; хост — `exo::ExoDiag::read(&mcu)`.

| Смещение | Тип | Поле |
|---|---|---|
| 0x00 | u32 | магия 0x4741_4944 («DIAG») |
| 0x04 | f32 | оценка температуры обмотки, °C |
| 0x08 | f32 | измеренная температура корпуса, °C |
| 0x0C | f32 | средний за 1 мс квадрат тока, А² |
| 0x10 | f32 | действующий предел тока, А |
| 0x14 | u32 | мс подряд в условии заклинивания |
| 0x18 | f32 | скорость сустава для заклинивания (фильтр 100 мс), °/с |
| 0x1C | u32 | 1 — оценка обмотки восстановлена после сброса сторожем |
| 0x20 | u32 | заклинивание: 0 — нет, 1 — идёт спад тока, 2 — защёлка |

### Регулирование
* Прерывание таймера **10 кГц**: аварийная кнопка, датчик угла, перегрузка по
  току; ПИ по току в фиксированной точке Q16 (у ядра нет FPU), усиления — в
  долях заполнения с поправкой на измеренное Vbat; обратный расчёт
  антинасыщения; заполнение ≤ 0.95.
* Каждый 10-й тик — **1 кГц** (`f32`, программная плавающая точка):
  * тепловая модель обмотки (стандартная I²t-защита двигателя): узел «обмотка»
    C_w·dT_w/dt = I²·R(T_w) − (T_w − T_корпуса)/R_wh, R(T) = R_ref·(1 + 0.00393·(T − T_ref)),
    C_w = τ_w/R_wh; I² — среднее квадратов 10 отсчётов тока за 1 мс; корпус —
    ИЗМЕРЕННЫЙ (ADC2), т. е. второй узел сети привязан к датчику. Явный Эйлер с
    шагом 1 мс и компенсированным суммированием (Кэхэн) в f32. После включения
    питания T_w := T_корпуса; оценка хранится в `.noinit` (магия + инверсия) и
    переживает сброс сторожем/программный;
  * предел тока = i_max·min(k_корпус, k_обмотка): k_обмотка = 1 до T_max − 25 °C,
    линейно до 0 к T_max, выше T_max драйвер выключен;
  * режим 1: τ = поддержка·(m_f·g·r_c + m_груз·g·L)·sin θ, i* = τ/(Kt·N·η);
  * режим 2: ПИД по углу (D — по измеренной скорости, фильтр 10 мс; интеграл
    копится только при |e| < 5°) + компенсация тяжести;
  * затем ×спад связи, ограничение ±i_max·k_T, мягкие пределы угла.
* Основной цикл: разбор команд, телеметрия, индикатор, «кормление» сторожа, `wfi`.

### Защиты (каждая — флаг и проверка в `reference_checks`)
| Бит | Защита | Реакция | Граница времени (проверено) |

Позиционный режим (стенд `bench`, J ≈ 0.1 кг·м²): 30° → 90° — установление в ±1°
не дольше 1 с (измерено ≈ 0.3 с), перерегулирование ≈ 0.6°, ошибка < 0.5°.

Привод maxon EC 90 flat + HD 50:1, сустав заклинен в позиционном режиме (стенд с
двухузловой тепловой моделью, 25 °C): защита от заклинивания срабатывает через
1.50 с, ток спадает за 0.2 с, драйвер выключается в 1.70 с, пик обмотки 27.9 °C.
Поддержка у предела тока с неподвижной рукой (режим 1) драйвер не выключает: за 30 с
от 65 °C ток плавно снижается по оценке обмотки (106 °C → 6.1 А). Если оператор раз за разом перезапускает привод
(режим 0 → 2, драйвер включён 95 % времени), обмотку бережёт тепловая модель:
за 150 с пик 107.3 °C (оценка 107.2 °C) при T_max = 125 °C; корпус к этому моменту
лишь 48 °C — по датчику корпуса защита сработала бы слишком поздно.

Ограничение: после включения питания оценка обмотки начинается с температуры
корпуса — если двигатель выключили горячим и сразу включили, оценка занижена
(до остывания). После сброса сторожем оценка сохраняется.

## 7. Проверки (вторым способом)

`sim_mcu::reference_checks()` — 41 сверка (`mcu.*`), см. `src/checks.rs`:
самопроверка против нативной сборки того же кода и против спецификации,
декодер против кодировок ассемблера LLVM, период таймера, ток поддержки против
расчёта вручную, позиционирование, все защиты с временами реакции, сторож,
заклинивание (время срабатывания, спад тока, отсутствие ложного срабатывания при
удержании в режиме поддержки), оценка обмотки прошивкой против тепловой сети стенда (f64), пик
обмотки при заклинивании, ток в полосе снижения против формулы. Тест
`tests/thermal.rs` дополнительно сверяет тепловую модель стенда и оценку прошивки
с моделью двигателя `sim-em` (`Motor`: точная экспонента тока, RK4).

## 8. Ограничения

* Модель времени приближённая (см. §1); кэш флеша, конвейер, задержки шины не моделируются.
* Нет режимов U/S, PMP, атомарных (A) и плавающих (F/D) команд, отладочного модуля.
* Невыровненный доступ всегда ловушка (железо ESP32-C3 тоже ловит).
* Периферия — идеальная: АЦП без шума, ШИМ усреднён, UART без скорости линии,
  радио без эфира (эфир — у хоста).
* `mtime` — глобальное время модели, сбросом не обнуляется.
* Обнаружение «двойного сбоя» предполагает, что обработчик исключения завершается `mret`.
