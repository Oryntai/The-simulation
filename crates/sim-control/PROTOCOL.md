# Стык контроллеров

`ControlContract` задаёт номера, полные имена, единицы, типы входов и сроки годности. Номера разрешаются принимающей стороной после установки моделей. Входы разных экземпляров фильтруются перед вызовом. Передавайте самый свежий отсчёт, включая отметку `valid = false`. Если последний отсчёт потерян или просрочен, предыдущее значение использовать нельзя. Два отсчёта одного канала с одинаковым временем доставки считаются неоднозначностью. У кадра отдельно проверяются возраст съёмки и возраст доставки. Возрасты включают границу.

`BuiltinConfig` задаёт блоки в порядке вычисления и привязывает их к выходам. `Affine` задаёт калибровку или линейную комбинацию, например ошибку регулятора. `InRange` выдаёт предикат для `Gate` или разрешения PID. При потере сигнала или разрешения PID сбрасывает интегратор и предыдущее значение ошибки. `PlanarTilt` объединяет две калиброванные компоненты ускорения, вычисленные в одной плоскости, и угловую скорость в рад/с. Подход предполагает пригодную для оценки наклона полосу модуля ускорения. `Rgb` вычисляет центроид всех совпавших пикселей по заданной оси. Координаты индексов пикселей начинаются с нуля.

`MissingOutput::Omit` означает инвалидирование прежнего значения этого выхода. `MissingOutput::Value` задаёт явное поведение при потере, например при остановке. Принимающая сторона проверяет результат повторно в виртуальный момент фактической доставки. `OutputChannel::max_age_ns` отсчитывается от времени исходного наблюдения. Ошибку обмена или исполнения нужно отразить в результате прогона и в политике принимающей цепочки.

`StreamTransport::open` принимает потоки стенда или симуляции. `ProcessTransport::spawn` запускает тот же обмен через stdin/stdout работника. `ExternalController::request` возвращает пару исходного запроса и ответа, пригодную для очереди доставки. `ControlContract::validate_response` проверяет эту пару в момент применения. Задержка очереди, такты приёмника и отказы задаются снаружи виртуальным расписанием. Синхронный обмен занимает один запрос за раз. Для отмены по часам внешний супервизор получает PID через `spawn_supervised`, `restore_supervised` или `fork_supervised` до рукопожатия.

Снимок сохраняет согласованные параметры и ограниченную по объёму историю выполненного обмена. Восстановление запускает независимый процесс с теми же аргументами и зерном. Оно снова выполняет каждый запрос и сравнивает байты ответов. При исчерпании бюджета и при неполном или аварийно оборванном обмене снимок возвращает явную ошибку. Сторона, которой нужен отпечаток прогона, учитывает исполняемый файл и конфигурацию работника.

## Двоичный формат v1

Каждое сообщение начинается с длины полезной нагрузки `u32`, затем следует полезная нагрузка. Все числа little-endian. Время и сроки заданы целыми наносекундами `u64`. `f64` передаётся побитово и должен быть конечным. Логическое значение занимает байт `0` или `1`. Строка передаётся как длина в байтах `u32` и байты UTF-8. Список начинается с количества элементов `u32`. Ограничение размера согласуется для всей полезной нагрузки, включая тип сообщения.

| Тип | Поля после байта типа, по порядку |
| --- | --- |
| `1` Hello, `2` Ready | Четыре байта `SIMC`, версия `u32 = 1`, предел полезной нагрузки `u32`, первый номер запроса `u64`, зерно `u64`, списки входов и выходов |
| `3` Request | Номер запроса `u64`, время наблюдения, список скаляров, список кадров |
| `4` Response | Номер запроса `u64`, список пар (номер выхода `u32`, значение `f64`) |
| `5` Rejected | Пусто. Сеанс после отказа заканчивается |

Вход Hello/Ready содержит номер `u32`, имя, единицу и байт типа. Тип `1` означает скаляр со сроком от доставки, тип `2` означает кадр с байтом формата, сроком от съёмки и сроком от доставки. Выход содержит номер `u32`, имя, единицу и срок.

Скаляр Request содержит номер входа `u32`, значение `f64`, время доставки и флаг пригодности. Кадр содержит номер входа `u32`, время съёмки, время доставки, ширину и высоту `u32`, байт формата, флаг пригодности, длину пикселей `u32` и их байты. Форматы `1` RGB8 и `2` DepthMm16 совпадают с раскладкой `sim-signal`. Хост передаёт свежие пригодные входы по одному на канал, в порядке номеров.

Работник проверяет схему и подтверждает параметры сообщения Hello в Ready. Запросы идут последовательно от согласованного номера, время наблюдения не убывает. Ответ повторяет номер запроса. После неполного сообщения, некорректного ответа или ошибки сеанса дальнейший обмен на этом канале прекращается.

## Нейтральный работник

`sim-control-worker` получает параметры позиционными аргументами. stdout предназначен для протокола, диагностика идёт в stderr.

```text
sim-control-worker РЕЖИМ БАЙТЫ ID_ВХОД ИМЯ_ВХОД ЕД_ВХОД ID_ВЫХОД ИМЯ_ВЫХОД ЕД_ВЫХОД СРОК_ВЫХОДА МАСШТАБ СМЕЩЕНИЕ ПРИ_ПОТЕРЕ ПАРАМЕТРЫ_РЕЖИМА...
scalar СРОК_ВХОДА
pid    СРОК_ВХОДА KP KI KD МИН_ИНТЕГРАЛ МАКС_ИНТЕГРАЛ МИН_ВЫХОД_PID МАКС_ВЫХОД_PID
rgb    СРОК_СЪЁМКИ СРОК_ДОСТАВКИ ОСЬ Rmin Gmin Bmin Rmax Gmax Bmax МИН_ПИКСЕЛЕЙ ПРОЕКЦИЯ...
```

Для `ПРИ_ПОТЕРЕ` допустимы `omit`, `error` и конечное число. Ось задаётся `x` или `y`. Проекция задаётся `pixel` или `bearing ЦЕНТР_ПИКС ФОКУС_ПИКС`. Общие масштаб и смещение применяются к вычисленному значению режима.

## Кинематика

В `Tree::new` передаются звенья с произвольным порядком, одним корнем и двумя позами крепления вокруг каждого соединения. Преобразование звена имеет вид `parent_to_joint · joint(q) · joint_to_link`. Положение в метрах, углы в радианах. В `Pose` кватернион задаётся как `[w, x, y, z]`. Координаты следуют порядку входных звеньев. Для шарового соединения это три компоненты вектора поворота, для свободного сначала три компоненты смещения, затем три компоненты вектора поворота. Пределы задаются покоординатно. Особые положения параметризации вектора поворота учитываются через численный ранг.

`TaskFrame` указывает точку на звене и неподвижную либо связанную со звеном систему отсчёта. Геометрический якобиан возвращает линейную и угловую скорость точки по каждой координате, выраженную в осях этой системы. Ранг относится к выбранным строкам и ветвям задачи. Обратная задача ищет локальное решение с заданными допусками, а статус недостижимости выдаёт по консервативной оценке расстояния. Рабочая зона хранит настройки равномерной сетки и фактически рассчитанные точки. Непрерывные пределы траектории относятся к координатным скоростям и ускорениям. Для проверки скоростей деталей, динамики и контакта нужны отдельные модели.
