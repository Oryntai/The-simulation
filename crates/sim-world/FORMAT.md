# Формат мира и устройства

`load_and_compile` принимает TOML мира версии 3. Пути файлов моделей отсчитываются от
файла мира. Пути сеток отсчитываются от файла, где задана геометрия. На этапе сборки
сетки встраиваются в текст MJCF. Для одинаковых входных данных порядок и текст стабильны.
`parse_world` и `parse_device` разбирают текст, проверяют версию и конечность чисел.
Связи, размеры, физические пределы и ссылки на файлы дополнительно проверяет `compile_world`.

У устройства формата 3 можно указать `schematic = "электрика.toml"` в корне документа.
Путь считается от файла устройства и должен быть относительным. При загрузке мира
проверяется, что схема доступна как текстовый файл. `load_and_compile_with_schematics`
возвращает разрешённые пути по именам экземпляров рядом с физическим миром.
Разбор электрического формата выполняет `sim-cli::electrical`. Модели без ссылки,
импорт URDF/MJCF и миграция формата 2 дают пустую запись для схемы.
Загрузчики, возвращающие один `CompiledWorld`, ставят барьер положительного
доказательства для заявленной схемы до подключения электрических проверок.

## Минимальный пример

Файл `мир.toml`. В примере выбран шаг 1 мс, а гравитация и параметры среды отключены
для проверки свободного движения.

```toml
format = 3
name = "Стенд"
seed = 19
physics_hz = 1000
gravity_m_s2 = [0.0, 0.0, 0.0]

[environment]
density_kg_m3 = 0.0
viscosity_pa_s = 0.0
wind_m_s = [0.0, 0.0, 0.0]

[[devices]]
name = "стенд"
file = "каретка.toml"
```

Файл `каретка.toml`. Размеры и плотность условного куба выбраны так, что его масса
равна 1 кг. Параметры трения и инерции оси заданы нулевыми для идеальной каретки.

```toml
format = 3
name = "Каретка"

[[links]]
name = "блок"

[links.joint]
kind = "slide"
axis = [1.0, 0.0, 0.0]
limits_m = [-0.5, 0.5]
damping = 0.0
friction_loss = 0.0
armature = 0.0
efforts = [{ name = "сила", dof = 0 }]

[links.mass]
kind = "geometry"
material = { name = "образец", density_kg_m3 = 1000.0, provenance = { estimate = "условная плотность для примера" } }

[[links.collision]]
shape = { kind = "box", size_m = [0.1, 0.1, 0.1] }

[[links.visual]]
shape = { kind = "box", size_m = [0.1, 0.1, 0.1] }
```

## Позиции, связи и геометрия

- Координаты и линейные размеры задаются в метрах, массы в килограммах, время в секундах,
  углы в полях `*_deg` в градусах. Поза содержит `position_m` и один из вариантов
  `quat_wxyz` или `rpy_deg`. Последний задаёт повороты вокруг неподвижных X, Y, Z
  в указанном порядке. Поза звена задаётся в кадре родителя.
- `hinge` и `slide` принимают произвольную ненулевую ось. Их начальная координата
  меняет начальную позу и численное значение координаты в MuJoCo. У `ball` начальный
  поворот включается в опорную позу, верхняя граница задаёт конус от этой позы.
  `free` располагается в корне, его начальное положение задаёт поза. `fixed` сохраняет
  кадр звена без степени свободы. `objects` создаёт независимые свободные тела.
- `connect` совмещает две точки, `weld` совмещает их позиции и ориентации.
  У передач `gear` и `belt` отношение связывает приращения координат.
  `screw` задаётся перемещением за оборот. `cable` ограничивает сверху взвешенную сумму
  длин ветвей, поэтому свободно провисает до натяжения. Ограничения численно мягкие.
- `mounts` описывает точки `mechanical`, `power` и `signal`, у каждой есть строка
  `interface`. `world.attachments` создаёт механические weld между точками одного
  интерфейса. Для `design` их позы уже должны совпадать. Для `runtime` связь
  изначально выключена. `set_attachment_active` принимает короткое имя записи.
  Электрические и сигнальные цепи используют свои модели и через weld не соединяются.
- `collision` и `visual` независимы. Размеры коробки и длина цилиндра полные.
  У капсулы длина относится к цилиндрической части. Сетка из файла может быть STL
  (двоичная или текстовая) или OBJ. OBJ принимает треугольники и выпуклые плоские
  многоугольники. STEP находится за границей импорта.
- `mass.kind = "explicit"` задаёт массу, центр и тензор
  `[Ixx, Iyy, Izz, Ixy, Ixz, Iyz]` с источником. `geometry` использует объёмы
  столкновения, `volumes` берёт отдельные инерционные объёмы. По каждому объёму можно
  уточнить материал или явную массу с источником. Сумма использует теорему Штейнера.
  Для объёма сетки нужны замкнутые согласованно ориентированные грани.
  Безмассовый `fixed` допустим как система координат.
- `strength_section` выделяет постоянное прямоугольное или круглое сечение в
  заданном направлении. Сетка и форма с переменным сечением дают `NotAnalyzed`.

## Импорт и сверка

- URDF импортирует звенья, инерции, обычные соединения, простую геометрию и цвет.
  Внешние адреса и `package://` требуют разрешения в локальный путь до импорта.
- MJCF импортирует механику тел, инерции, сетки, позы, связи и линейные передачи.
  Для настроек `option` есть `import_mjcf_world`. Динамический привод, `default`,
  нелинейная передача, несколько соединений в одном теле и параметры решателя,
  которых нет в схеме, возвращают ошибку с именем элемента или атрибута.
  Сеточный вывод массы требует `mesh inertia="exact"`.
- `migrate_v2` берёт массу и инерцию из прежнего механического расчёта. Для
  моделей, ссылающихся на каталог приводов, передайте прежний `sim_device::Catalog`.
  Полный исходный файл остаётся в `legacy_v2.original`. Контактная геометрия и
  сведения о прочности требуют новой постановки.
- `verify_compiled` возвращает отдельно сверку инерций и результат динамической
  сверки. Для геометрической массы MuJoCo независимо интегрирует те же объёмы.
  Для явно заданной инерции сверяется передача данных, включая ориентацию главных осей.
  Второй движок выборочно проверяет кинематику, матрицу масс и силы C+G.
  Реакции контакта, замыканий, передач и сил среды этой сверкой не покрыты.
  Применимость метода, происхождение массы и ограничения физической модели учитываются отдельно
  через `simplifications`.

Математические соглашения ограничений, единицы и параметры MJCF описаны в
[справочнике MuJoCo](https://mujoco.readthedocs.io/en/stable/XMLreference.html).
