# Управление в контуре

Сначала загрузить `CompiledWorld` в `Runtime`, установить физические модели
и зарегистрировать необходимые каналы истины. Затем разобрать `control.toml` и
вызвать `control::install`. Передать исходные байты мира, каталогов, задачи и
критериев в `RunSpec`. Для каждого привода передать его собственную пару
`ModelPort::Drive { channel, accepted }` по результату установки модели, а
при наличии двоичного входа питания передать `ModelPort::Power { channel }`.

`FileAssets { base }` разрешает пути относительно файла сборки. Для внешней
программы байты ресурса проверяются против исполняемого файла. `worker_ids`
показывает PID уже открытых процессов. `ControlAssets::worker_started` передаёт
PID супервизору до начала рукопожатия.

До первого такта `Runtime::set_initial_velocities` устанавливает обобщённые
скорости по имени соединения и номеру степени свободы. `Runtime::joint_velocity`
считывает фактическое значение из движка. `Runtime::set_channel_delays` принимает
`channel:<имя>` для провода или `observation:<имя сигнала>` для добавочной
задержки доставки наблюдения. `channel_delay_ns` возвращает установку,
`channel_delay_observed` подтверждает состоявшуюся доставку с этой задержкой.
Для провода подтверждение сверяет отдельно приход к приёмнику и его получение
на такте платы. У внешнего процесса изоляция ОС остаётся `NotAnalyzed`.

## Формат

Плоское подмножество TOML. Поддерживаются корневое поле `version = 1`, таблицы
`[[имя]]`, однострочные строки, числа, логические значения, массивы и комментарии.
Любое неприменимое, неизвестное или повторное поле приводит к ошибке.
В каждой таблице нужен `source` с источником параметров. Время в наносекундах
целое. Частота задаётся как `rate_hz` либо дробью `rate_hz / rate_den`.

| Таблица | Поля и назначение |
| --- | --- |
| `controller` | `name`, `kind` (`builtin` или `external`), `rate_hz`, `program`. Для внешнего также `args`, `input_latency_ns`, `input_jitter_ns`, `output_latency_ns`, `output_jitter_ns`, `request_hz`, `request_max_age_ns`, `queue_capacity`, `max_message_bytes`. Необязательный `max_history_bytes` позволяет сохранить и восстановить сеанс через проверенное повторное исполнение. |
| `input` | `controller`, полное имя `signal`, `unit`, `kind` (`scalar`, `rgb8`, `depth_mm16`). Возраст задаётся `max_age_ns` для скаляра или парой `max_capture_age_ns`, `max_delivery_age_ns` для кадра. |
| `output` | `name`, `controller`, `target`, `target_kind`, `unit`, `max_age_ns`, необязательный `fallback`. `goal` создаёт именованный скаляр. `effort` пишет в свободный вход силы или момента. `drive` требует `ack` по полному имени и явного `fallback`. `power` пишет 0 или 1 в объявленный вход питания. |
| `board` | `name`, `catalog`, `image`, `rate_hz`, необязательный `config` с байтами конфигурации. `end_sample = true` включает блокирующую доказательство квадратуру по выходу конца того же интервала при совпадающих тактах платы и физики. |
| `board_input` | `name`, `board`, `signal`, `unit`, `kind` (`adc` или `gpio`), `port`, `max_age_ns`, `scale`, `offset`, `fallback`. После аффинного преобразования АЦП получает вольты, GPIO получает 0 или 1. Без `fallback` на АЦП фиксируется разомкнутый вход. Для GPIO уровень разрыва обязателен. |
| `board_action` | `id`, `at_ns`, `board`, `kind`. Для `gpio` задать `pin`, `high`. Для `reset` и `restart` можно передать `config` с новыми байтами. `restart` заново открывает исходный образ с новым началом шкалы тактов платы. Действие применяется на такте обмена платы. |
| `driver` | Как `output`, с полем `board` вместо `controller`. Дополнительно `pin`, `quantity` (`logic`, `duty`, `high_s`, `period_s`), `scale`, `offset`. `direction_pin` меняет знак при низком уровне. `enable_pin` вместе с `enable_active_high` задаёт разрешение. Для длительностей требуются `period_min_s` и `period_max_s`. |
| `bus` | `name`, `board`, `bus`, `signal`, `model` с путём к профилю регистра, `max_age_ns`. Для SPI обязателен `chip_select`. Угол читается из сигнала модели датчика в единицах профиля. |
| `packet` | `name`, `kind` (`uart`, `ble`, `wifi`, `scheduled_radio`), `capacity`, `max_age_ns`. Стороны `from_board` и `to_board` с соответствующими `from_port`, `to_port`. Опущенная сторона означает вход из данных или доставку в журнал. UART задаёт `delay_ns`. `scheduled_radio` задаёт `delay_ns`, `rssi_dbm` и `max_bytes` для связи с расписанием из данных. Радио BLE и Wi-Fi задаёт `interval_ns` для BLE или `attempt_ns` для Wi-Fi, а также `loss`, `rssi_dbm`, `attempts` и `max_bytes`. |
| `transmission` | `at_ns`, `route` без другого отправителя, `bytes`. |
| `stimulus` | `at_ns`, `target`, `unit`, `value`. Канал стимула должен быть свободен от других писателей. Стимул имеет собственное происхождение в журнале. |
| `fault` | `id`, `target`, `at_ns`, необязательный `until_ns`, `kind`. Для `stuck` требуется `value`, для `delay` требуется `delay_ns`. |

Имена целей отказов получаются из разрешённой проводки. `ControlRun::paths`
содержит именованные возможности, включая цели верхнего уровня, участвующие
в каждом пути. Поддержанные действия:

- `sensor:<сигнал>`: `drop`, для скаляра также `stuck`.
- `wire:<провод или выход>`: `drop`, для числового выходного канала также
  `stuck`, для выходного входа питания также `power_off`.
- `actuator:<вход>`: `drop`, `stuck`. `power:<вход>`: `drop`, `power_off`.
- `bus:<шина>`: `drop`. При обрыве I²C получает NACK, SPI не получает ответ.
- `channel:<маршрут>` и `transport:<контроллер>/request` или `/response`:
  `drop`, `delay`. Для сигнала цели `channel:<цель>`: `drop`, `stuck`.
- `controller:<имя>`: `pause`. `board:<имя>`: `pause`, `power_off`.

Профиль встроенного графа в `program` имеет `version = 1`, таблицы
`[[block]]` и `[[bind]]`, у каждой есть `source`. Ссылки на блоки идут по
нулевому индексу. Порядок отличается от порядка сигналов. `bind` задаёт
`output`, `node`, `missing` (`omit`, `error`, `value` с полем `value`).
Названия блоков и параметры:

- `scalar` (`signal`), `constant` (`value`), `affine`
  (`nodes`, `weights`, `offset`).
- `in_range` (`input`, `min`, `max`), `gate` (`input`, `condition`).
- `pid` (`error`, необязательный `enable`, `kp`, `ki`, `kd`,
  `integral_min`, `integral_max`, `min`, `max`).
- `tilt` (`sin`, `cos`, `rate`, `acceleration_min`, `acceleration_max`,
  `time_constant_s`).
- `rgb` (`signal`, `min`, `max`, `min_pixels`, `axis`, `projection`).
  Проекция `bearing` требует `center_px` и `focal_px`, проекция `pixel`
  возвращает пиксельную координату.

В `args` внешнего процесса целые аргументы вида `$input:полное_имя`
и `$output:имя_выхода` заменяются номерами из согласованной схемы. Программа
запускается без оболочки, остальные аргументы передаются буквально.

## Шкала контура и журнал

На одной метке завершается прежний интервал физики, фиксируются начало и конец
отказов, публикуются измерения, выполняются связь, контроллеры, приводы и
оценщики. Имена экземпляров упорядочиваются при сборке. Цель доступна после
текущей фазы контроллеров. Нижний уровень читает её в свой следующий такт.
Вычисленная между физическими границами сила влияет на следующий интервал.
Плата исполняет предыдущий интервал с уже зафиксированными входами и вводит
новые значения на своей границе обмена. Журнал сохраняет такт CPU и время
события платы отдельно от времени, когда рантайм его получил.

`Runtime::observe()` в замкнутом контуре отдаёт последний доставленный отсчёт,
включая недействительный. При разомкнутом просмотре рядом с отметкой отказа
сохраняется последнее пригодное показание для совместимости старых клиентов. `control::measurement_time` возвращает время измерения и
доставки скаляра. В `Observation`, передаваемом контроллеру, `Sample.at`
означает время измерения, чтобы штатная проверка свежести не продлевала срок
из-за задержки. Обе метки, исходные и прочитанные значения доступны в
`ControlRun::events`. Для кадров сохраняются обе штатные метки, а в журнал
идёт отпечаток пикселей.

`CommandDelivered` фиксирует поступление на вход тракта,
`CommandPresented` фиксирует передачу модели, `CommandApplied` содержит факт
и вид подтверждения. `PhysicsInterval` указывает левую границу успешно
проинтегрированного интервала. `ModelReport` указывает такт, на котором модель
опубликовала значение. `ModelAcceptance` дополнительно связывает подтверждение
с номером команды и фактическим тактом через `Truth::command_sequence` и `Forces::accept`. Позднее и неоднозначное подтверждение
записывается как `ModelAcceptanceUnattributed`. Эффект следует сверять с
отдельным каналом истины. `FaultRequested` и `FaultApplied` разделяют
расписание и момент прохождения через целевой компонент. Например, прекращение
пакетной доставки следует подтверждать исходом пакета.

Для оценки брать `control::run(&runtime)` при `origin() == RunOrigin::Live`,
сверять `identity`, `reached_horizon`, покрытие `paths`, ограничения моделей,
фактические применения и результат в истине. Загруженные числовые журналы и
`install_replay` служат диагностике. Прямой `Runtime::act` в контуре блокирует
запись в занятые каналы и маркирует происхождение остальных внешних команд.
Программный ввод `ControllerBindings` маркируется отдельно.

`try_snapshot`, `restore` и `fork` проверяют доступность продолжения внешнего
сеанса. `fork` открывает отдельный процесс и сверяет его ответы на предшествующие
запросы. `ControlRecording` хранит запись в памяти. При `install_replay` модели,
платы и отказы исполняются в той же шкале, внешние ответы воспроизводятся из
записи после проверки отправленных запросов. `verify_replay` сверяет оба журнала.
