# Журнал стенда

## Первый натурный опыт

Статус — **не проверено на реальном устройстве**. Положите журнал штатного входа образца №4 в
`devices/stage7/04-real.csv`. Впишите в [04-capture.toml](04-capture.toml) ревизию собранного
экземпляра и укажите те же конструкцию и ревизию в журнале. При существенной смене узлов,
монтажа, прошивки, проводки или датчиков назначьте новую ревизию. Запишите на одной временной
шкале период, ширину и монотонный номер каждого завершённого импульса в момент его измерения,
углы рычага и клавиши, ток и напряжение шины. Положительное направление угла и нули
сопоставляются с осями соединений в файле мира. Укажите эти привязки и схему измерения в паспорте лога.

```sh
cargo run --offline -p sim-reality -- run devices/stage7/04-capture.toml devices/stage7/04-real.csv
```

Штатный профиль проверяет и импортирует захват. Для сопоставления этого входа с симуляцией
нужен мир с позиционным регулятором и импульсным входом, настроенным по конкретному экземпляру.
В каталоге параметры диапазона периода и ширины, соответствия ширины углу и таймаута отмечены
как неизвестные. Команда на разомкнутом мосту определяет другой эксперимент.

Если стенд позволяет измерить **фактическую знаковую скважность на мосту**, разрешение питания
моста и ток обмотки, используйте [04-bridge.toml](04-bridge.toml) с теми же механическими
каналами. Он воспроизводит команды в существующем мире этапа 2 и сравнивает угол рычага,
угол клавиши и ток. Ток питания внешней сервы и ток её обмотки имеют одинаковую единицу,
но относятся к разным участкам электрической цепи. Для стенда задайте те же начальные положения,
полярность, нули и питание, что указаны в модели, либо внесите измеренную конфигурацию в свой мир.

```sh
cargo run --offline -p sim-reality -- run devices/stage7/04-bridge.toml devices/stage7/04-bridge-real.csv
```

## Формат CSV версии 1

UTF-8, разделитель запятая, кавычки и многострочные поля не используются. Вторая строка задаёт
конструкцию, ревизию и горизонт в целых наносекундах от общего нуля. В конце стоит количество
записей, которое фиксирует сам регистратор. Ниже синтетический пример формата с двумя строками.

```csv
sim-reality,1,synthetic
build,блок,схема-а,1000000
time_ns,signal,unit,seq,value,valid
0,положение,m,0,0,1
1000000,положение,m,1,,0
end,2
```

- `synthetic` помечает генератор или симуляцию. `recorded` помечает физическую запись.
- Имена и единицы должны совпадать со схемой TOML буквально. Угол пишется в `rad`, время в имени
  столбца `time_ns` задано в наносекундах. Числа конечные, десятичный разделитель — точка.
- Глобальный порядок по времени неубывающий, в одном канале строго возрастающий. `seq`
  начинается с 0 отдельно для каждого канала. Номер присваивается у источника до передачи и выгрузки.
- Пропуск наблюдения пишется как пустое `value` с `valid=0`, когда схема разрешает его явным
  `allow_invalid = true`. Такой журнал пригоден для диагностики без записи о происхождении.
  Команды всегда действительны. У скалярных команд обязателен исходный
  отсчёт в 0 нс, очередное значение удерживается до следующей записи.
- `event` допускает нерегулярные метки. `periodic` требует `first_ns` и `period_ns`
  и проверяет каждый такт до горизонта. `packet` требует `group` и задаёт отсутствие команды
  до первого полного пакета. Все каналы группы обновляются вместе. В рантайме такой вход
  привязывается к тройке периода, ширины и номера импульса.
- Для графиков `exact` берёт только одноимённую метку, `linear` требует соседние действительные
  значения с интервалом не более `max_gap_ns`, `hold` удерживает предыдущий действительный отсчёт
  на возраст до `max_age_ns` внутри области ряда. Явно недействительные точки сохраняются.
  Для границы ошибки на сравнимых отсчётах укажите `uncertainty` в единице канала по паспорту
  калибровки. Без неё поле верхней границы остаётся пустым.
- Сдвиг равен «симуляция минус стенд». JSON показывает точки, число сопоставимых записей, смещение,
  СКО и максимальный модуль разницы. При отсутствии кривой или пар модель получает `not_analyzed`.
  Имена приводов и датчиков из скомпилированного мира должны быть в `models`.
  Для состояния механики `qpos[i]` и `qvel[i]` идут в порядке координат MJCF. Для сравнения
  доставки наблюдений используйте метки доступности, для состояния — метки физического измерения.

## Запись о происхождении и установка калибровки

Запустите команду без четвёртого аргумента, чтобы получить отпечаток `log_fingerprint`. Если
физический журнал выпустил владелец стенда, укажите этот отпечаток, идентификатор опыта, метод и
дату калибровки измерительного тракта, область применимости и ревизию в отдельном TOML. Пустые
поля ниже подлежат заполнению.

```toml
log_fingerprint = ""
capture_id = ""
calibration = ""
scope = ""
[build]
design = "стенд-04"
revision = ""
```

Передайте путь к записи последним аргументом. Для записи с пометкой `recorded` и совпадающими
версией и отпечатком определённые параметры из журнала без пропусков получают `source = "measured"`.
Для опыта задержки также требуется полное соответствие отправленных и принятых маркеров.
Опыт без определённых параметров остаётся в секции идентификации. Отпечаток FNV-1a
идентифицирует байты. Достоверность пометки о физической записи удостоверяет владелец стенда.
Если нужны параметры для
следующего прогона, добавьте `[[simulation.apply]]` с точным именем модели и `target` из
`drive_motor`, `drive_coupling`, `drive_delay`, `sensor_delay`, `camera_optics`.
Перед установкой для каждой группы должны определиться все необходимые параметры, а штатный
установщик каталога проверяет физические ограничения. Исполнение обновляет копию мира в памяти.
Если сравнение запущено на том же журнале, оно помечается как сравнение по журналу калибровки.
Поле доказательства безопасности остаётся `not_analyzed`.

## Схема опытов

В профиль добавляется `[[experiments]]` с `model`, таблицей `input` и таблицей `criteria`.
Имена в `input` ссылаются на наблюдения, перечисленные в `channels`. Для регрессий метки входов
синхронны. Критерии включают `max_condition`, `max_reduced_chi_square` и таблицу
`max_half_width` с пределом полуширины по каждому параметру. Выбирайте их по требуемой
точности, области применения модели и измерительной неопределённости, в единицах параметра.

| `input.kind` | Входы и параметры |
|---|---|
| `dynamics` | `axis` (`angular` или `linear`), имена `acceleration`, `velocity`, `effort`, калиброванные `sigma_effort` и `min_abs_velocity`. Для `coulomb`, `viscous`, `inertia` нужен участок независимых ускорений и скоростей обоих знаков. Усилие измеряется на выбранной оси с компенсацией известных нагрузок. Для `drive_motor` это момент и кинематика на валу двигателя с включённым вкладом входа передачи в инерцию. |
| `coupling` | `axis`, имена `relative_position`, `effort`, калиброванные `sigma_position`, `min_abs_effort`. Медленное нагружение в обе стороны позволяет отделить полный `backlash` от смещения нуля и `stiffness`. Положение берётся в координатах выхода передачи. |
| `delay` | Имена `sent` и `received` с одинаковым целым номером маркера в значении, `sigma_ns` для разности меток, `clock_offset_bound_ns` для систематической ошибки. Оценка `delay` в секундах относится к этим двум концам пути. |
| `camera` | Имена `x`, `y`, `z` в метрах в оптической системе (X вправо, Y вниз, Z вперёд), `u`, `v` в пикселях, `width`, `height`, `sigma_px`, `max_iterations`. Точки должны покрывать обе оси и несколько радиусов. Определяются `fx`, `fy`, `cx`, `cy`, `k1`, `k2`, `k3`, `p1`, `p2`. |

Интервалы 95% индивидуальные. Они используют заявленное СКО независимых ошибок в отклике,
с поправкой вверх по остаткам. При неизвестной корреляции, заметной ошибке входных координат
или существенной систематике эту модель интервала требуется перепроверить на независимой серии.
Для оптики интервал локальный около найденной калибровки. Сопоставление в кадре опирается на
численные координаты меток. Сырые изображения и отпечатки кадров другого смысла.

Модуль не оценивает совместную ковариацию установки камеры, экспозицию, глубинный шум, трение
страгивания, демпфирование передачи, гистерезис контакта, меняющуюся во времени задержку и
полосы вне записанного опыта. Для них нужны другие измерительные постановки.

## Нейтральная проверка из данных

```sh
cargo run --offline -p sim-reality -- run devices/stage7/acceptance/profile.toml devices/stage7/acceptance/capture.csv
```

Две независимые направляющие воспроизводят дискретный баланс `v += Fh/m`, `x += vh`.
Четыре пары маркеров дают среднюю задержку 174 мкс. К записанным положениям после нуля
добавлены сдвиги +2 и −1 мкм для проверки расчёта разрыва. Происхождение журнала синтетическое.

## Передача заверенного ряда в кампанию

Добавьте в установку сценария `measurement_build = { design = "...", revision = "..." }`
и проверку `verification = { kind = "measurement", limit = ... }` для класса
`measurement`. Лимит содержит имя и единицу измеренного канала. Окно задаёт границы
и максимальный интервал, а установщик подтверждает допустимость метода и источника.

Из JSON первой кампании возьмите `detail.build_fingerprint` и полный
`detail.summary.key` нужной строки. В пакет версии 1 внесите `[[records]]` с полями
`experiment` (сборка/опыт), `run` (полный ключ), `build_fingerprint`,
`signal` (имя и единица), `profile` (путь к TOML со схемой) и `capture` (путь к CSV).
Для доказательного вывода в `[[records]]` укажите `uncertainty` как верхнюю границу
абсолютной погрешности каждой точки в единице канала по протоколу калибровки.
В `[records.receipt]` укажите запись владельца в формате выше вместе с `build`.
Пути считаются от файла пакета. Горизонт захвата должен совпасть с завершённой строкой.

```sh
cargo run --offline -p sim-cli --bin sim-run -- --campaign MANIFEST.toml --measurements RECORDS.toml --json
```

Передача проверяет пригодность происхождения и привязку. Оценщик проверяет покрытие
и сравнивает интервал каждой точки с пределом. Неизвестная погрешность или пересечение
предела оставляют открытый вывод. Для дискретного канала события нужна точная
регистрация состояния, для которой погрешность кодирования равна нулю.
