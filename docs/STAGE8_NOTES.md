# Инженерная приёмка этапа 8

Статус этапа — не принят. Повторная проверка подтвердила точную модель, побитовый журнал и 21 обзорную текстуру для семи задач, а также 16 доставленных кадров RGB. Клиент называет отметку экстремума максимумом ряда. Для составной строки кампании ещё нужна привязка дочернего прогона, сетки, журнала и события из оценщика. Фактическая посадка требует обмеров.

Для штатного сценария `sim-run --campaign MANIFEST --repeat KEY --view ARCHIVE` выгружает тот же живой журнал, который использует оценщик. Клиент сверяет ключ, отпечатки входов и журнала, режим и горизонт. На [новом блоке](../devices/stage8/acceptance/campaign.toml) клиент открыл `Rejected` на 4 000 000 нс. Ход 14 мкм при пределе 8 мкм совпал с независимой суммой четырёх шагов Euler.

Ниже зафиксирована первая проверка до выгрузки точной модели и повтора штатного сценария.

```sh
cargo run --offline -p workshop -- --suite devices/stage8/suite.json
cargo run --offline -p workshop -- --platform devices/stage8/rod-world.toml --duration 0.08
RUST_TEST_NOCAPTURE=1 cargo test --offline -p workshop
cargo test --offline -p sim-verify --test platform_boundary
```

Оба теста используют заданный `CARGO_TARGET_DIR`. Проверка окна загружает программные текстуры без создания окна и сохраняет обзорные кадры только во временный каталог.

## Время, датчики и вердикт

- На независимом стержне с шагом 1 мс курсор 37 000 003 нс использовал позу от 37 000 000 нс. Сдвиг 7,03 мм совпал с суммой шагов Euler, камера находилась на X = 132,03 мм. В текстуре на 24 мс появился RGB 96×72 с началом захвата в 0. При сравнении запись Б закончилась на 30 мс, а её кадр и значение исчезли на общем курсоре 37 000 003 нс. Полоса в 24 пикселя на четверти шкалы сохранила исходные пиксели кадра.
- Стержень открывается обычным `--platform` из двух TOML. На отдельном блоке клиент и прямой вызов CLI выдали 35 845 одинаковых байт SIMLOG и 2 317 байт JSON. Высота после 100 шагов по 1 мс составила 0,9495 м. У семи задач совпали отпечатки журналов при повторных запусках.
- Отчёт кампании сверяется по статусу и покрытию. В короткой кампании из `decision-campaign.toml` три вердикта окна совпали с JSON конвейера — `Rejected`, `NotProven` и `PassedSimulation` со ступенью `BenchOnly`. Противоречивые сочетания вердикта, покрытия и готовности отклоняются. Отдельно открытый журнал сбрасывает прежнюю привязку к отчёту.
- Переход к худшему событию проверен на связанной отметке 37 000 003 нс. Вариант, горизонт и наличие отметки проверяются до изменения курсора. Для семи штатных задач доступен диагностический просмотр. `--repeat` в короткой кампании вернул ту же худшую строку и отпечаток её входов. Журнал и отметка события отсутствуют.

## Что требуется для §4.11

1. Мир, датчики, силы. `sim-cli` должен выдавать с журналом точный мир выбранного прогона, схему координат и записанные кадры камеры. В пяти контрольных сценах доступна проектная геометрия. Для камеры без записанных пикселей показан проектный вид из места установки.
2. Задачи, сравнение, худший случай. Нужен экспорт строки кампании с ключом, дочерним режимом, отказом, выборкой, сеткой, зерном, журналом и временем события из отчёта. Ключ без времени позволяет повторить строку, а курсор остаётся без подтверждённой отметки.
3. Участник. Для точной посадки нужны мир выбранного прогона и обмеры креплений. `sim-runtime` нужен версионированный формат пространственных реакций и событий креплений. Клиент сейчас читает поддержанные диагностические записи SIMLOG v2.
