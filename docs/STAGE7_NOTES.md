# Строки для README и ARCHITECTURE

## README

### Связь с реальностью (этап 7)

`cargo run --offline -p sim-reality -- run PROFILE.toml LOG.csv [RECEIPT.toml]` читает
журнал с целыми наносекундами и единицами, воспроизводит команды в MuJoCo и выдаёт JSON
по моделям и кривым. Определение трения, инерции, люфта, жёсткости, задержки и девяти
внутренних параметров камеры показывает чувствительность, обусловленность и интервал 95%.
Для натурной записи установку параметров связывают с ревизией конструкции, калибровкой
измерительного тракта и отпечатком журнала.
[Формат журнала и путь для образца №4](devices/stage7/FORMAT.md).

### Чего пока нет

Образец №4 не проверен на реальном устройстве. Профиль для штатного импульса принимает
журнал. Для сравнения штатного входа требуются диапазоны периода и ширины, зависимость
команды от ширины, таймаут и модель регулятора конкретного экземпляра. Для опыта с доступом
к мосту есть профиль воспроизведения углов и тока обмотки. Камера сверяется по координатам
меток, физические кадры и параметры установки, экспозиции и глубины требуют отдельных опытов.

## ARCHITECTURE.md, §7.7

### Этап 7. Связь с реальностью

`sim-reality` импортирует наблюдения в `sim_signal::SignalTable` и `Sample`, команды в
`Command`. Сетка, посылки, счётчики до транспорта, единицы, конечность чисел и завершение
журнала проверяются до запуска. Команды проходят через обычный `Runtime::act`; в нуле они
предшествуют событиям, позже применяются после событий совпадающей метки. Данные кадра,
состояние модели и наблюдения датчиков имеют разную семантику.

Идентификатор использует баланс усилий вне страгивания, наклоны нагруженных сторон передачи,
разность парных меток и Брауна — Конради с известными координатами мишени. SVD
масштабированного якобиана проверяет вырождение и даёт условные чувствительность и
обусловленность. Интервалы учитывают шум, остатки и, для задержки, границу ошибки часов.
Схема отклика и заранее заявленные пределы исключают запись параметра при недостатке данных.
[Взвешенный МНК NIST](https://www.itl.nist.gov/div898/handbook/pmd/section1/pmd143.htm).
[Модель проекции OpenCV](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html).

Отчёт разделяет сравнение кривых, происхождение и калибровку. Источник «замер» применим
к определённым параметрам конкретной ревизии и модели. Явный пропуск или потеря парного
маркера оставляют журнал пригодным для диагностики без записи о замере.
Опыт без определимых параметров сохраняется
в отчёте как `NotAnalyzed`. Достоверность происхождения зависит от владельца записи и
регистратора. Для безопасности отчёт этапа 7 сохраняет `NotAnalyzed`.

Независимая приёмка проверила 15 параметров в трёх шумовых сериях. Максимальная ошибка
0,558075%, контрольное расхождение проекции до 0,025003 px. Нейтральный стенд из данных
воспроизвёл две механические кривые. В имитации записи владельца установка 174 мкс задержки
сдвинула доступный отсчёт на отметке 3 мс с 15 до 9 мкм по ручному балансу движения.

#### Чего пока нет на этапе 7

Натурная сверка и независимый стендовый журнал пока отсутствуют. Реальный замер требует
проверить соответствие монтажных осей, шкал, временных меток, единиц и начального состояния.
Автоматический перенос проверенных стендовых рядов в кампанию этапа 6 потребует вызова
`record_measurement` из `sim-cli` с отпечатком сборки, полным ключом прогона и подтверждённой
калибровкой. Положительный вывод по опасности требует пригодности эксперимента к конкретному
пути и отдельной процедуры приёмки. Синтетические отчёты остаются диагностикой.
